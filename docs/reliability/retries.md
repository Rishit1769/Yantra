# Retries

The model gateway implements bounded retries for explicitly retryable provider failures. Its default is one attempt (no retry). Configuring multiple attempts requires digest-bound routing-policy approval and is capped at five attempts; delays use exponential backoff with jitter and bounded provider retry hints. Retried inference can incur duplicate cost. A timeout or network error marked retryable may have reached the provider, so the caller should account for possible repeated inference charges.

The gateway emits attempt-numbered request/retry/failure events. It does not provide durable attempt storage, a circuit breaker, or rate limiting. Automatic retries do not apply to validation, authorization, unsupported-capability, policy-denial, or other non-retryable errors. Tests cover successful retry after a classified transient failure, refusal to retry a non-retryable failure, and the approval requirement for multiple attempts. Provider-specific 429 hint bounds, cancellation during backoff, and cross-provider retry economics remain areas for additional targeted tests; no live provider requests are used by these tests.
