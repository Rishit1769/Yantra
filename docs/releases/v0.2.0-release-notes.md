# YANTRA v0.2.0 Release Notes

**Status:** Prepared release candidate; not tagged or published.

- Package: `yantra==0.2.0`
- Intended Git tag: `v0.2.0`

YANTRA 0.2.0 is an alpha Python package release candidate for the core contracts and model-gateway foundation. It is not a production-ready agent runtime.

## Included

- **Core runtime foundation:** typed messages, budgets, results, lifecycle states, events, structured logging, in-memory storage, and a validated tool registry. There is no complete agent execution loop, tool dispatcher, or authorization engine.
- **Model gateway:** explicit provider registry, provider/model identifiers, model catalog, deterministic/manual routing and approved fallback, model-scoped capability declarations, normalized completion responses, and normalized streaming events.
- **Provider adapters:** OpenAI Responses, Anthropic Messages, Gemini, DeepSeek Chat Completions, Ollama, OpenRouter, OpenCode Zen/Go, and a configurable OpenAI Chat Completions-compatible subset. This does not mean arbitrary APIs, models, or protocol variants work.
- **Capability handling:** tool calling, structured output, streaming, usage, and other capabilities remain deployment/model-specific. Unknown capabilities are not inferred; required capabilities fail closed unless positively declared.
- **Tool-call proposals:** supported adapter paths serialize and normalize tool proposals and streaming deltas. YANTRA does not execute proposed tools in the gateway or smoke CLI. A wire-format test does not establish a model's live tool eligibility.
- **Credentials:** `env://` references and optional OS keyring support keep raw values out of configuration arguments and normal diagnostics. Provider-specific validation does not uniformly prove inference entitlement.
- **Error and response handling:** typed provider errors, bounded diagnostic fields, response size and timeout limits, reasoning-aware response normalization, and private provider-namespaced reasoning metadata that is not presented as visible answer text.
- **Token budgets and smoke CLI:** the developer CLI provides offline mock commands and opt-in live commands for Ollama/OpenCode. Live inference requires explicit billing opt-in for OpenCode. Offline commands make no provider requests. The smoke CLI is not a general-purpose YANTRA command line or agent runner.
- **Endpoint transport:** the default transport filters resolved IP addresses at connection time and connects to the selected IP while retaining hostname-based TLS verification. Loopback remains available for local inference; non-loopback private destinations require explicit trust. Caller-injected HTTPX clients own their DNS/IP, redirect, TLS, proxy, egress, and credential-forwarding policy.
- **Licensing:** Apache License 2.0, SPDX `Apache-2.0`; see the root [LICENSE](../../LICENSE).

## Provider Verification

Automated adapter tests use mocked HTTP transports. The detailed per-capability statuses are in the [provider verification matrix](../features/provider-verification.md).

For `opencode-go/deepseek-v4.1-flash`, the supplied user report records non-streaming completion, streaming completion with visible text, reasoning metadata preservation, and usage reporting. This evidence was not independently rerun for this candidate. Tool-call support for this exact model remains **UNKNOWN** and the gateway continues to fail closed. Other providers do not have live verification evidence recorded here.

## Verification

- Local macOS test suites passed: 132 tests on Python 3.12.15, 3.13.15, and 3.14.7.
- Ruff check and formatting passed; Pyright completed with zero errors, warnings, or information messages.
- `uv audit --locked` reported no known vulnerabilities or adverse project statuses in 34 packages. The uv audit command is experimental.
- Locked sync and lock consistency checks passed. Wheel and sdist builds succeeded with version `0.2.0`.
- Both archives installed in separate isolated Python 3.12 environments outside the checkout. Installed metadata, import path, license, User-Agent, and CLI entry point were verified. `yantra-smoke --help`, `offline`, `offline --stream`, `offline --tool-call`, and combined streaming/tool-call offline tests passed for both archives without provider requests.
- The GitHub Actions workflow configures Ubuntu, macOS, and Windows with Python 3.12, 3.13, and 3.14. No hosted run was available during preparation; configuration is not a passing result.
- Windows compatibility is therefore unverified. This package does not claim Windows support until the actual Windows CI jobs pass.
- No live provider catalog lookup or inference request was made while preparing these notes.

## Known Limitations

- No agent run loop, tool execution/authorization policy engine, general-purpose CLI, durable storage service, skill runtime, or production deployment has been validated. These are not part of this release.
- Provider adapters have protocol/mock coverage, not general live compatibility. Credentials, account access, model availability, data residency, and feature support depend on the specific provider/model/account.
- OpenCode Go's catalog does not establish account entitlement or per-model tool calling. The model-specific tool-call status above remains unknown.
- DNS/IP controls and redirect denial apply to YANTRA's default HTTPX transport. Applications that inject their own HTTPX client must provide equivalent DNS/IP, redirect, TLS, proxy, egress, and credential-forwarding controls.
- Hosted cross-platform CI has not run for this release candidate, including Windows. No claim of cross-platform compatibility is made.
- The API is pre-1.0 and may change. The package is alpha, not production-ready.

This document describes a candidate only. A tag or PyPI publication requires all gates in the [release process](../development/releasing.md), a passing final audit, and separate explicit authorization.
