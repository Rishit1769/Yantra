# Model Provider Contract

An adapter implements the async `ModelProvider` contract (`provider_id`, declared `ProviderCapabilities`, and `complete(ModelRequest)`); streaming is an optional `StreamingModelProvider` contract. Catalog discovery and credential validation are optional adapter methods. Request includes normalized messages/content blocks, model selection, capability requirements, generation settings, output schema if supported, request ID, and deadline. Response preserves provider/model/request identity, content blocks, tool proposals, finish reason, nullable token usage, and only allowlisted metadata.

Capability set is explicit and deployment-specific: streaming, tool calls, structured output, cancellation, context limit, and usage may be unknown. Unknown does not mean supported; a required capability must be positively declared and otherwise fails before sending. Provider fallback is an explicitly approved gateway policy, never implicit adapter behavior. Credentials resolve at call time from a secret source and are excluded from persistence/logging. Provider errors map to stable typed categories: authentication, authorization, quota/rate-limit, timeout, unavailable/network, invalid request, model unavailable, unsupported capability, refusal, and unknown. YANTRA-002 provider HTTP tests use mocks; no live-compatibility claim is made.
