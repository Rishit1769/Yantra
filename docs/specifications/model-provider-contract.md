# Model Provider Contract

An adapter implements async capability discovery/resolution, request completion, optional streaming, cancellation, and normalized provider error/usage mapping. Request includes messages/content blocks, model selection, capability requirements, output schema if supported, limits, request ID, and deadline. Response preserves provider/model/request identity, content blocks, tool proposals, finish reason, usage (nullable), and raw metadata only when allowlisted/redacted.

Capability set is explicit and deployment-specific: streaming, tool calls, parallel tool calls, structured output mode, vision/input types, context limit, and usage detail may be unknown. A required-but-unsupported capability fails before sending. Adapters must not claim a capability based solely on family name when deployment configuration differs. Provider fallback is a router policy, never implicit adapter behavior. Credentials resolve at call time from a secret source and are excluded from persistence/logging. Provider errors map to stable categories: authentication, rate-limit, timeout, unavailable, invalid request, unsupported capability, content/policy refusal, and unknown.
