# Documentation Standards

Mark proposals and implementation status; never describe an unverified command/API as working. Feature docs include every section in [feature standard](../features/_standard.md), unique requirement IDs, measurable acceptance criteria, dependencies, and open questions. Contracts are normative and versioned. Diagrams use Mermaid and must match text. Links are relative and checked. Security, retention, migration, and failure behavior are documented alongside happy paths. No benchmark, certification, release, or test claim without evidence.
